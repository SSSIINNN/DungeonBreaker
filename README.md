# 던전깨기(DungeonBreaker)

Roblox로 개발하는 **3인칭 로그라이크 액션 RPG**입니다. 로비에서 던전에 입장해 몬스터와 전투하고, 방을 클리어하면 다음 방에 도전하거나 로비로 돌아가는 플레이 흐름을 만들고 있습니다.

현재는 **기본 전투와 던전 진행 흐름을 구현한 프로토타입**입니다. 방 구조와 몬스터 배치는 고정되어 있으며, 무작위 던전 생성·보상·성장 시스템은 아직 구현되지 않았습니다.

## 개발 목표

- 입장 → 전투 → 클리어 → 다음 방 선택으로 이어지는 명확한 도전 경험
- 사망 후 재도전을 통해 반복해서 플레이할 수 있는 로그라이크 구조
- 서버가 전투와 이동 상태를 관리하고, 클라이언트는 입력과 화면 표시를 담당하는 구조
- 방 구성, 적, 보상과 성장 선택지를 확장할 수 있는 게임 기반 마련

## 개발 환경

| 도구 | 역할 |
| --- | --- |
| Roblox Studio | 게임 실행, 플레이 테스트, 장면 확인 |
| Luau | 서버·클라이언트 게임 로직 작성 |
| Visual Studio Code | 소스 코드 편집 |
| Rojo 7.7.1 | 파일 기반 프로젝트 빌드 및 Studio 동기화 |
| Aftman | `aftman.toml`에 지정된 Rojo 버전 관리(선택 사항) |

## 현재 구현된 기능

아래는 **소스 코드에서 확인한 구현 범위**입니다. 모든 항목의 Studio 플레이 테스트가 완료되었다는 의미는 아닙니다.

| 구분 | 구현 내용 |
| --- | --- |
| 로비와 입장 | 돌 바닥·벽·횃불·노란 포털을 코드로 생성하고, 입구 근처에서 E 키로 던전 입장 |
| 개인별 던전 | 같은 서버 안에 플레이어별 독립된 방과 몬스터를 생성하고 소유자·도전 번호 관리 |
| 기본 전투 | 전방의 가까운 몬스터 1마리 공격, 거리·방향·장애물·공격 간격을 서버에서 검사 |
| 몬스터 | 방마다 석상 수호자 3마리 생성, 플레이어 추적 및 근접 공격 |
| 피해량 설정 | `CombatConfig.luau`에서 플레이어 공격력 25, 몬스터 공격력 5를 각각 조정 |
| 클리어와 진행 | 몬스터 전멸 후 앞벽이 열리고 파란 출구 생성. 출구를 걸어서 통과하면 다음 방·로비 선택 UI 표시 |
| 다음 방 | 방 번호를 증가시키고 같은 구성의 새 방과 몬스터 생성. 현재 난이도 증가 로직은 없음 |
| 사망과 재도전 | 던전에서 사망하면 다시 도전·로비 복귀 선택. 재도전은 1번 방부터 시작 |
| HUD와 입력 | 상태, 방 번호, 남은 몬스터 수, 체력 표시. 마우스·키보드·게임패드 공격 입력과 화면 버튼 연결 |
| 3인칭 카메라 | Roblox 기본 Classic 카메라 사용, 줌 거리 6~18로 설정 |
| 서버 검증 | 생존 여부, 구역, 거리, 방 소유자, 도전 번호, 진행 상태 검사 및 중복 이동·선택 방지 |

입장과 복귀는 별도 Roblox 서버로 이동하는 방식이 아니라 **현재 서버 안에서 캐릭터 위치를 변경하는 방식**입니다. 플레이어가 퇴장하면 해당 방과 연결된 이벤트를 정리합니다.

### 조작

| 행동 | 입력 |
| --- | --- |
| 이동·카메라 | Roblox 기본 캐릭터 조작 |
| 던전 입장 | 노란 입구 근처에서 E / 게임패드 X / 표시된 상호작용 프롬프트 |
| 공격 | 마우스 왼쪽 버튼 / F / 게임패드 R2 / 화면의 공격 버튼 |
| 클리어 후 목적지 선택 | 파란 출구를 통과한 뒤 화면 버튼 선택 |
| 사망 후 재도전·복귀 | 화면 버튼 선택 |

모바일과 게임패드의 입력 연결은 코드에 포함되어 있지만, 실제 기기에서의 사용성과 화면 배치는 추가 검증이 필요합니다.

## 개발 예정 기능

로그라이크 완성을 위한 후속 개발 항목이며, 아래 기능은 현재 코드에 구현되어 있지 않습니다. 세부 범위와 우선순위는 플레이 테스트 결과에 따라 조정할 예정입니다.

- 무작위 방 구성과 다양한 던전 배치
- 몬스터 종류·행동 패턴·보스 및 방별 난이도 변화
- 무기·스킬·아이템과 클리어 보상, 성장 선택지
- 진행 데이터 저장 및 불러오기
- 전투 애니메이션·사운드·시각 효과와 조작감 개선
- 모바일·게임패드 화면 최적화 및 다중 플레이어 안정성 검증

## 프로젝트 구조

```text
DungeonBreaker/
├─ src/
│  ├─ server/
│  │  ├─ init.server.luau   # 서버 진입점: Dungeon.start() 실행
│  │  ├─ Dungeon.luau       # 플레이어 상태, 입장·클리어·재도전, RemoteEvent 관리
│  │  ├─ World.luau         # 로비·방·포털·횃불 생성 및 출구 개방
│  │  ├─ Travel.luau        # 생존·거리·구역 검증, 위치 이동과 출구 영역 판정
│  │  ├─ Combat.luau        # 몬스터 생성·추적·공격 및 플레이어 타격 판정
│  │  └─ CombatConfig.luau  # 플레이어와 몬스터의 피해량 설정
│  ├─ client/
│  │  └─ init.client.luau   # HUD, 공격 입력, 목적지·사망 선택 UI
│  └─ shared/
│     └─ Hello.luau         # Rojo 초기 예제 모듈; 현재 게임 로직에서 사용하지 않음
├─ tests/
│  └─ PortalCombatCheck.luau # Studio에서 수동 실행하는 회귀 검사 모듈
├─ default.project.json     # Rojo 서비스 연결, 카메라·기본 장면 설정
├─ aftman.toml              # Rojo 7.7.1 버전 고정
├─ AGENTS.md                # 프로젝트 개발 지침
├─ .gitignore               # 빌드 결과·임시 파일·민감 정보 제외 규칙
└─ README.md
```

### Rojo 연결 경로

| 로컬 경로 | Roblox Studio 경로 |
| --- | --- |
| `src/server` | `ServerScriptService.Server` |
| `src/client` | `StarterPlayer.StarterPlayerScripts.Client` |
| `src/shared` | `ReplicatedStorage.Shared` |

`init.server.luau`와 `init.client.luau`는 각각 `Server`, `Client` 스크립트가 됩니다. 서버 모듈은 `Server` 스크립트의 자식으로 배치됩니다. `tests`는 기본 프로젝트에 연결하지 않아 일반 플레이에 자동 실행되지 않습니다.

### 에셋과 빌드 결과

현재 로비·방·몬스터·포털·공격 효과·UI는 Luau와 Roblox 기본 객체로 생성합니다. 소스에는 별도 업로드 모델, 이미지, 사운드, 애니메이션 ID나 외부 모듈 의존성이 없습니다. 저장소에 필요한 별도 로컬 에셋 파일도 현재 없습니다.

`DungeonBreaker.rbxlx`는 소스로 다시 만들 수 있는 빌드 결과이므로 Git에서 제외합니다. 원본 모델·이미지를 추가할 경우 함께 관리할 수 있도록 `.rbxm`, `.rbxmx`, 이미지 파일 전체를 제외하는 규칙은 사용하지 않습니다. 현재 제공된 스크린샷·영상 파일이 없어 미디어는 포함하지 않았습니다.

## 받아서 실행하기

### 1. 도구 준비

Roblox Studio와 Git을 설치합니다. 소스 수정에는 VS Code를 사용할 수 있습니다. Rojo CLI는 [`7.7.1` 공식 릴리스](https://github.com/rojo-rbx/rojo/releases/tag/v7.7.1)에서 운영체제에 맞는 파일을 받아 PATH에 등록하거나, Aftman이 설치된 환경에서 프로젝트 루트의 `aftman install`을 실행합니다. Aftman이 도구 신뢰 확인을 요청하면 공식 `rojo-rbx/rojo` 도구인지 확인합니다.

VS Code 확장 설치만으로 터미널의 `rojo` 명령이 제공되는 것은 아닙니다. 설치 방법은 [Rojo 공식 설치 문서](https://rojo.space/docs/v7/getting-started/installation/)를 참고하세요.

### 2. 프로젝트 받기와 빌드

```sh
git clone https://github.com/SSSIINNN/DungeonBreaker.git
cd DungeonBreaker
rojo --version
rojo build default.project.json -o DungeonBreaker.rbxlx
```

`rojo --version`이 `Rojo 7.7.1`을 표시하는지 확인합니다. Git 없이 GitHub의 **Code → Download ZIP**으로 받아 압축을 해제해도 빌드할 수 있습니다.

### 3. Studio에서 실행

1. Roblox Studio에서 생성된 `DungeonBreaker.rbxlx` 파일을 엽니다.
2. Explorer에서 `ServerScriptService.Server`, `StarterPlayer.StarterPlayerScripts.Client`, `ReplicatedStorage.Shared`가 있는지 확인합니다.
3. **Play(F5)**를 누릅니다. 캐릭터가 필요한 게임이므로 Run만 실행하는 방식과 구분합니다.
4. 로비에서 시작하여 노란 포털로 접근한 뒤 E 키를 누릅니다.
5. 아래 체크리스트로 전투·클리어·사망 흐름을 확인합니다. Output 창의 오류도 함께 확인합니다.

빌드된 파일을 실행하는 데 Rojo 연결을 계속 유지할 필요는 없습니다. 편집 중에는 터미널에서 다음 명령을 실행하고 Studio의 Rojo 7 플러그인에서 `localhost:34872`에 연결합니다.

```sh
rojo serve default.project.json
```

플러그인이 없다면 `rojo plugin install` 또는 [공식 설치 안내](https://rojo.space/docs/v7/getting-started/installation/)를 이용합니다. 연결 시 적용될 변경 사항을 확인하고 동기화합니다. [빌드와 동기화 안내](https://rojo.space/docs/v7/getting-started/new-game/)도 참고할 수 있습니다.

- 프로젝트에 별도의 모델·이미지·영상 원본이 없는 것을 확인했습니다.

**이번 준비 작업에서는 Studio 플레이 테스트와 `PortalCombatCheck.luau` 실행을 수행하지 않았습니다.** Rojo 빌드 성공만으로 게임 실행 중 동작이나 아래 항목의 통과를 보장하지 않습니다.

### 기존 회귀 검사 모듈 실행

`tests/PortalCombatCheck.luau`는 포털의 문틀 덮임, 통과 가능한 파란 가림판, 출구 중복 생성 방지, 클리어·출구 선택 상태, 피해량 설정의 독립 적용을 assert로 검사합니다. 전체 플레이 흐름을 대신하는 테스트는 아닙니다.

1. **테스트용으로 연 Studio**에서 Play를 시작하고 서버 컨텍스트로 전환합니다.
2. `ServerStorage`에 임시 `ModuleScript`를 만들고 이름을 `PortalCombatCheck`로 설정합니다.
3. 해당 모듈의 내용을 `tests/PortalCombatCheck.luau` 파일 전체로 교체합니다.
4. 서버 Command Bar에서 실행합니다.

```lua
print(require(game.ServerStorage.PortalCombatCheck)(game.ServerScriptService.Server))
```

통과하면 `PASS: portal coverage, opaque passable backing, single exit/choice, independent attack damage`를 반환합니다. 실패하면 assert 오류가 나타납니다. 검사는 임시 월드를 만들고 피해량 설정을 잠시 변경한 뒤 정리·복구하므로 다른 플레이 테스트와 동시에 실행하지 않습니다. Play를 종료하면 실행 중 추가한 임시 모듈은 유지되지 않습니다.
